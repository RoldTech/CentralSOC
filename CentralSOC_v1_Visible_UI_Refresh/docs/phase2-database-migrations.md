# CentralSOC Phase 2 — baseline database migrations

## What was implemented

- `alembic.ini`, `migrations/env.py`, and an autogenerated, fixed baseline revision reflecting the existing SQLAlchemy schema.
- `regexsoc/db/migration_baseline.py`: defensive one-time adoption for legacy databases. It requires exactly the expected table names, no existing `alembic_version`, and zero SQLAlchemy metadata differences. It refuses mismatch without schema changes.
- Three automated tests for initial upgrade, data-preserving baseline adoption, and refusal of incomplete schema.
- Alembic declared as an application dependency.

## Important: Protect your database

Make a verified, offline backup of the database **before** any migration or stamp. Shut down application writers for the backup and migration. Never point tests at a real database. Do not delete `instance/regexsoc.db`. This phase does not reset databases.

The project currently also uses SQLAlchemy `create_all()` in some runtime paths. That legacy behavior remains for compatibility, but **does not version a database**. Use the commands below on a new isolated database when starting a new deployment.

### New, empty database

In the project root, set `DATABASE_URL` to a new SQLite file or PostgreSQL database and run:

```powershell
python -m pip install -r requirements.txt
$env:DATABASE_URL = 'sqlite:///instance/centralsoc-new.db'
alembic upgrade head
alembic current
```

### Existing, already populated RegexSOC database

After backing it up and stopping concurrent writers, set `DATABASE_URL` to the existing database and run:

```powershell
$env:DATABASE_URL = 'sqlite:///instance/regexsoc.db'
python -m regexsoc.db.migration_baseline
alembic current
```

The adoption command **stamps only**; it does not create or modify existing application tables. If it refuses due to differences, investigate those differences manually rather than forcing `alembic stamp head`. After successful adoption, use `alembic upgrade head` for future schema revisions.

### Testing

```powershell
python -m pytest tests/test_migrations.py -q
python -m pytest -q
```

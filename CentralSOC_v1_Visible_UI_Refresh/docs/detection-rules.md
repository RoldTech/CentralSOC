# Detection Rules
_Generated by `python -m regexsoc rules docs`. Do not edit by hand._
Severity is derived from the risk score using the configurable bands (0-29 LOW, 30-59 MEDIUM, 60-79 HIGH, 80-100 CRITICAL). Risk scores are a triage aid, not a probability of compromise.

## RULE-001: Failed SSH Login

- **Category:** Authentication
- **Severity:** LOW
- **Risk contribution:** +10
- **Default state:** enabled
- **How it works:** Event rule matched against: `raw`.

**What it detects:** A single failed SSH authentication attempt.

**Why it matters:** Failed logins are the raw material of brute-force and credential-stuffing attacks.

**Example log:** `Mar 10 10:15:01 web01 sshd[1234]: Failed password for root from 203.0.113.5 port 54321 ssh2`

**Regex pattern(s):**

```regex
\bFailed (?:password|publickey|keyboard-interactive/pam) for\b
```

**Possible false positives:** Users mistyping passwords; expired credentials; misconfigured automation.

**Recommended analyst action:** Note the source IP and account. No action for isolated failures; watch for repetition.

## RULE-005: Possible Port Scan

- **Category:** Network
- **Severity:** HIGH
- **Risk contribution:** +65
- **Default state:** enabled
- **How it works:** Correlation: the pattern(s) select candidate events; window logic is in the parameters.

**What it detects:** One source IP hits many distinct destination ports in a short window (firewall logs).

**Why it matters:** Port scanning is reconnaissance: attackers map open services before choosing an exploit.

**Example log:** `[UFW BLOCK] SRC=203.0.113.50 DST=10.0.0.5 PROTO=TCP SPT=40000 DPT=22 (x 15+ ports)`

**Regex pattern(s):**

```regex
\bSRC=\S+.*\bDPT=\d+
```

**Parameters:** `{'kind': 'distinct', 'field': 'destination_port', 'threshold': 15, 'window_seconds': 60}`

**Possible false positives:** Authorised vulnerability scanners, monitoring/health probes, peer-to-peer traffic.

**Recommended analyst action:** Check whether the source is internal or external, review reputation, confirm the firewall blocked the probes, and look for follow-up access to any port that answered.

## RULE-006: SQL Injection Indicator

- **Category:** Web Attack
- **Severity:** HIGH
- **Risk contribution:** +70
- **Default state:** enabled
- **How it works:** Event rule matched against: `request`.

**What it detects:** SQL syntax appearing in a request (UNION SELECT, tautologies, time-based functions...).

**Why it matters:** Injected SQL can expose or modify database contents.

**Example log:** `GET /item.php?id=1%27%20OR%201=1-- HTTP/1.1`

**Regex pattern(s):**

```regex
(?i)\bunion\b[\s/*]+(?:all[\s/*]+)?select\b
```
```regex
(?i)\b(?:or|and)\s+['\"]?(\d+)['\"]?\s*=\s*['\"]?\1\b
```
```regex
(?i)'\s*(?:or|and)\s*'
```
```regex
(?i)\b(?:sleep|benchmark|pg_sleep|waitfor\s+delay)\b\s*\(?\s*['\"]?\d
```
```regex
(?i)\binformation_schema\b|\bxp_cmdshell\b|;\s*(?:drop|truncate|delete)\s+(?:table|from)\b
```

**Possible false positives:** Developer tooling, security scanners, forum posts that discuss SQL.

**Recommended analyst action:** Review the affected endpoint and application logs, use parameterized queries, validate input, and check the database for unexpected reads or errors around this time.

```regex

```

## RULE-008: Directory Traversal Indicator

- **Category:** Web Attack
- **Severity:** HIGH
- **Risk contribution:** +65
- **Default state:** enabled
- **How it works:** Event rule matched against: `request`.

**What it detects:** Parent-directory sequences (../) including URL-encoded and double-encoded forms.

**Why it matters:** Traversal attempts to read files outside the intended directory.

**Example log:** `GET /download?file=..%2f..%2f..%2fetc%2fpasswd HTTP/1.1`

**Regex pattern(s):**

```regex
\.\.[/\\]
```

**Possible false positives:** Rare: badly built relative links, some legacy clients.

**Recommended analyst action:** Review web server logs, validate and canonicalize file paths in the application, keep sensitive files outside the web root and enforce access controls.

## RULE-009: Command Injection Indicator

- **Category:** Web Attack
- **Severity:** HIGH
- **Risk contribution:** +75
- **Default state:** enabled
- **How it works:** Event rule matched against: `request`.

**What it detects:** Shell metacharacters followed by common commands, or JNDI/shell-path payloads.

**Why it matters:** Successful command injection means arbitrary code execution on the server.

**Example log:** `GET /ping?host=8.8.8.8;cat%20/etc/passwd HTTP/1.1`

**Regex pattern(s):**

```regex
(?i)(?:;|\|\|?|&&|`|\$\()\s*(?:cat|ls|id|whoami|uname|wget|curl|nc|ncat|bash|sh|powershell|cmd(?:\.exe)?|ping|nslookup)(?:\s|$|\)|`)
```
```regex
(?i)\$\{\s*jndi\s*:
```
```regex
(?i)/bin/(?:ba)?sh\b
```

**Possible false positives:** Admin panels that legitimately accept commands; unusual but harmless query strings.

**Recommended analyst action:** Review the endpoint for shell calls, avoid passing input to a shell, use allow-lists, and inspect the host for unexpected processes or outbound connections.

## RULE-013: Suspicious User-Agent

- **Category:** Web Attack
- **Severity:** MEDIUM
- **Risk contribution:** +40
- **Default state:** enabled
- **How it works:** Event rule matched against: `user_agent`.

**What it detects:** User-Agent strings of well-known scanners and attack tools.

**Why it matters:** Tool signatures identify automated scanning. Attackers can spoof UAs, so absence proves nothing.

**Regex pattern(s):**

```regex

```


**Possible false positives:** Your own security team's scanners; penetration tests.

**Recommended analyst action:** Confirm whether this is an authorised scan; otherwise review the requests it made and consider blocking.
